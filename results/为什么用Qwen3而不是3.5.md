## 我为什么放弃 Qwen3.5
我知道，您看到 `为什么用Qwen3而不是3.5.md` 这个文件时，第一反应可能是："这人是不是搞不定新模型就退缩了？" 或者 "明明可以用 vLLM/修改源码/调长 prompt 解决，为什么要回退版本？"

答案是：我费了一上午（从发现 Qwen3.5 输出 `&lt;think&gt;` 标签导致全 50.00 分，到尝试各种参数配置，到发现官方文档给的方案在 transformers 原生 API 下无效，到被 AI 的过度对齐幻觉气笑）什么都没干成，只是证明了"在我当前的知识水平下，无法在不引入额外技术债务的前提下关闭这个功能"。再去折腾 vLLM 部署或源码修改，真的还算"轻量级文本风格分析"吗？还算"方法论民主化"吗？

再者，我的最终评估体系里明确包含"可及性（Accessibility）"和"知识门槛"维度，这个项目的核心卖点之一就是"任何人都能我的条件下复现我的实验"。如果我为了适配 Qwen3.5 的强制思考模式，再专门跑去研究vLLM 部署（增加 CUDA 版本依赖和系统级配置）、修改 transformers 库源码（破坏环境可移植性）、或者把 prompt 改成长篇大论并写复杂的正则过滤逻辑（增加代码复杂度），不仅耽误了我的实验时间，还违背了我自己定的"民主化"原则。

所以我选择了技术上最务实的方案：回退到 Qwen3-4B/8B，没有强制思考、能用 transformers 原生 API 直接加载，符合我所有的约束条件。这确实显得我很菜，但我的项目本来就追求State of the Availability而不是State of the Art，如果您能用三分钟搞定这个问题，那您确实比我强，但我作为非科班的独立研究者，我的实验设计本来就不是给三分钟能搞定的专业选手准备的，而是给"只能用低门槛方案"的人准备的，请理解我的坚持。

## 第二部分：我尝试过但失败的全程记录：我真的搞不定怎么关闭思考模式

### 我尝试过但失败的方法（按时间顺序）

1. **在 `model.generate()` 传 `enable_thinking=False`**
   - 结果：`ValueError: The following 'model_kwargs' are not used by the model: ['enable_thinking']`
   - 说明：transformers 的 generate 接口不认这个参数

2. **在 `tokenizer()` 传 `chat_template_kwargs={"enable_thinking": False}`**
   - 结果：被完全忽略，输出仍有 `&lt;think&gt;` 标签
   - 说明：这个参数似乎只在 OpenAI API 格式下有效，transformers 原生无效

3. **修改 `model.config.enable_thinking` 和 `model.generation_config.enable_thinking`**
   - 结果：`AttributeError`，这两个对象根本没有 `enable_thinking` 属性
   - 说明：Qwen3.5 的思考模式不是通过标准 config 控制的

4. **在提示词加入阻止思考的标签**
   - 这是Qwen3.5-plus给出的方案：在 prompt 里加`\no_think`标签
   - 结果：被忽略（原因不明）
   - 甚至导致Qwen3.5-plus出现了过度对齐幻觉：当我吐槽"你是4B亲爹，管管你儿子"时，开始以"Qwen3.5 开发者"身份道歉，并编造"经过 24 小时深度调试"的细节，实际上什么都没解决

5. **参考官方文档的 vLLM 方案**
   - 尝试用 vLLM 的 API 参数 `chat_template_kwargs={"enable_thinking": False}` 同样无效

6. **在提示词输入“不准思考”等内容**
   - 问题：15句参考文本已占用大量token（约800-1000），再加限制词可能挤占测试文本空间或触及max_length上限
   - 结果：未深入尝试（基于前述第4点，推测Qwen3.5思考模式为架构级强制，可能靠提示词搞不定）

## 附录：意外发现 8B 的鲁棒性

虽然回退到 Qwen3 是因为 3.5 的技术故障，但在 Qwen3 系列内部，8B 相比 4B 展现出了惊人的脱敏鲁棒性飞跃（Spearman ρ: 0.56→0.89），接近 MiniLM (ρ=0.95) 水平。这证明了在极端低资源下，参数规模临界点的存在——4B 只能依赖词汇，而 8B 已能捕捉结构特征。
