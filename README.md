# Synecdoche
1.项目定义
核心问题：资源受限条件下，轻量级方法能否可靠地完成文本风格判别任务？它们的优势区间在哪里？
硬约束：
数据：游戏角色台词695句，短文本，无人工标注
算力：RTX 5060Ti单卡16G，无法加载7B以上模型
优势评价指标（用数学工具找最优）：
性能：在内容无关测试集上，与人类基准相关系数>0.7
效率：推理延迟<100ms/句，显存占用<8GB，复现难度<2小时
可解释性：每条预测能追溯到具体特征或训练样本
成本效益：本地零成本vs API每千句费用，能用LoRA就不用全参数微调
蹭热点：低资源NLP，边缘计算，AI民主化
2.语料库构建
采集：爬台词，清洗
内容-风格解耦：自动构建替换词表（对比游戏vs通用文本词频），删除游戏专有词
质量控制：人工抽检10%
训练集/验证集划分：样本量小，选择尽量节约的方式
3.核心方法（双路径独立）
O1：可解释特征工程
O2：轻量模型微调（主力）
O2c：对比学习探索（可选）
4.基线系统（全覆盖）
B0：词袋模型
B1：n-gram
B2：标点指纹
B3：TF-IDF
B4：预训练编码器零样本（MiniLM）
B5：小型LLM零样本（Qwen3B）
B6：小型LLM轻量微调（LoRA）
B7：云端API成本基准（DeepSeek）
5.测试集构建
手工风格梯度（100句）
压力测试集（20句含专有词）
第三方盲评与ICC检验
6.评估体系
性能指标（相关系数、F1）
效率指标（算力、复杂度、实现难度/专业知识水平）
稳健性检验（压力测试性能差）
综合评价（帕累托曲线）
7.学术产出
论文结构（Methodology/Experiments/Limitation）
核心图表（评估曲线、失败日志）
附录（评分问卷、LoRA调参记录）
投稿目标：arXiv（画饼的最大半径：ACL/EMNLP findings/demo/workshop）
8.工具化与部署（整活部分）
Gradio网页演示（含系统稳健性/风控措施/彩蛋）
API封装（评语系统）
一键安装脚本/零基础复现指南（针对简单方法）
产品迭代（含数据使用合规）
9.检查点
Q1：语料与B0-B4-基线
Q2：O1/O2b主实验
Q3：O2c与B4-LoRA探索
Q4：工具化与论文
