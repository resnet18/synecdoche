# Synecdoche
1.项目定义

核心问题：资源受限条件下，轻量级方法能否可靠地完成文本风格判别任务？它们的优势区间在哪里？

硬约束：

数据：游戏角色台词695句，短文本，无人工标注

算力：RTX 5060Ti单卡16G（降级到8G）

内容-风格解耦：不能让模型学到风格 = 关键词

无监督/自监督：不能在训练阶段引入人为预设标准（比如：给模型提供“我要吃饭”打0分，“今天天气真好”打1分这样的例子）

>防杠，不只是任务方面无监督，已经确保实验所用模型的预训练过程也是无监督/自监督方式

专家知识：不涉及任何语言学专业训练

评价指标：

性能：在内容无关测试集上，互认的相关系数 (>0.6认为有显著一致性)

效率：推理延迟，显存占用，复现难度

可解释性：每条预测能追溯到具体特征或训练样本

成本：本地零成本 vs API每千句费用

技术门槛/学习成本：需要什么程度的ml知识？

蹭热点：低资源NLP，边缘计算，AI民主化

2.语料库构建

采集：爬台词（通过MediaWiki的API通道），清洗

内容-风格解耦：通过自动匹配和人工规则删除游戏专有词（这里实践过程中发现真没招了，只能几乎全靠人工）

质量控制：人工抽检10%

训练集/验证集划分：样本量小，选择尽量“节约“的方式

3.核心方法（双路径独立）

O1：可解释特征工程（与句长无关的特征）

O2：MiniLM + 对比学习（SimCSE） # 只有这一种无监督（其实是自监督）方法

O3：ELECTRA-small 冻结权重

4.基线系统

模型基线：

B0 词袋模型

B1 n-gram

B2 标点指纹

B3 TF-IDF

B4 word2vec（有神经网络，但CPU能跑）

B5 MiniLM zero-shot

B6 RoBERTa + SimCSE

B7 Qwen3-4B 15-shot ICL，无参考分数，禁用CoT

B8 Qwen3-8B 同上

B9 DeepSeek API 同上

B10 Kimi API 同上

人类基线（根据可靠性原则，不认为人类是基准，作为另一组基线参与）

H0 玩家（n=4）

H1 路人（n=3）

H2 一个NLP背景的玩家（n=1）

H3 我自己（n=1）

组分消融版本：

B2 可以视为O1消融

B4-pretrained 使用预训练的词向量（fastText）

B5 O2的冻结版，前面已经说明

B6-frozen 冻结，不微调

O2-probe O2一样的配置，但改为只训练头部

5.测试集构建

预实验测试集：脱敏的原台词（70句）

消融测试集：从预实验测试集还原标签的原台词（70句）

最终测试集：脱敏的原台词（70句）+其他文本（140句），详见“完整测试集说明”

压力测试：含专有词但没意义+边缘输入（比如单个标点符号）+对抗样本

6.评估体系

输入消融实验：用还原标签的测试集，比较脱敏vs还原的一致性，用来判断模型是否稳健 (>0.8视为足够稳健)

>注：本项目所称“输入消融实验”指输入层的词汇消融（Input/Lexical Ablation），不是一般意义上“拆除组分测试”的消融实验，特此说明。

最终测试：判断主实验和基线（包括API和人类）能否互认

性能指标：排序一致性的相关系数，MSE，MAE，偏差

效率指标：算力（显存占用），复杂度，实现难度/专业知识水平

10. 风险预案

全凉了：转为失效分析

部分方法寄了：附录收录

- **B5 (MiniLM), B6 (RoBERTa)**: 支持纯离线，无需配置
- **B7/B8 (Qwen3)**: 首次下载需要联网，后续支持完全离线
  - 如遇 `SSL/ConnectError`，脚本会自动降级到本地缓存模式
  - 无需手动设置环境变量
